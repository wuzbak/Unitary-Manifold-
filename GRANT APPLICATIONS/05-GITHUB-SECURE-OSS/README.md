# GitHub Secure Open Source Fund

**Status at 2026-11-06:** applications described as rolling. Selected projects receive **$10,000 per project** paid directly to maintainers via GitHub Sponsors in three tranches: $6,000 at program start, then $2,000 at the six-month and 12-month check-ins. Participants also commit time to the security program and follow-up reporting. This is maintainer funding, not a general corporate R&D grant; do not count in-kind credits or services as cash.

## Fit

Potentially useful for one public AxiomZero software project if it has a clear open-source license, credible governance, meaningful external adoption, and a specific security improvement plan. The current repository demonstrates substantial internal engineering and testing, but the evidence ledger does **not** establish external adoption or critical ecosystem dependency. That is a material weakness; do not imply otherwise.

GitHub's published eligibility criteria require the applicant to be a current project maintainer, the project to have a clear open-source license and governance, and demonstrable community traction and adoption. The repository evidence ledger does not establish those project-level facts for any candidate; identify a qualifying project and verify the maintainer, adoption, and supported-region requirements before applying. Internal test counts do not satisfy these criteria.

## Proposed security scope

Choose a maintained public product with a clear threat model. Potential work could include a dependency inventory, secure release process, vulnerability reporting and response, permissions review, security-focused tests, and remediation of findings. Select only controls that are not already complete. Do not promise that software will be “secure” or “vulnerability free.”

## Draft application paragraph

We maintain [specific public project] and seek to improve its security posture for [verified users/use]. The proposed work will establish a baseline, prioritize risks with an external reviewer, implement [specific fixes/controls], and publish a concise security roadmap and completion report. Outcomes will be measured by [reproducible metrics], not by unsupported claims of adoption or risk elimination.

## Before applying

- Confirm current application form, invited/applicant rules, eligible region/payment recipient, and program commitments.
- Identify external users and provide verifiable adoption evidence if requested.
- Choose no more than one or two core maintainers; confirm program hours and public reporting requirements.
- Confirm who receives the funds and tax/accounting treatment before application.
- Prepare an OSS-specific threat model and security work plan.
