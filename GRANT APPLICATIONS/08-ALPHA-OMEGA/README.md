# Alpha-Omega Seasonal Grant

**Instrument:** grant for security improvements to critical open-source software.
**Status:** Alpha-Omega describes a quarterly 12-week process. The published seasonal pattern opens submissions on the first day of each quarter's intake month, followed by review/co-design and then decisions/disbursement in month three. Check the live calendar for exact dates. An award ceiling was not verified in this research.

## Fit assessment

The mission is to protect society by improving the security of critical OSS through direct maintainer engagement and expert analysis. AxiomZero should not assume its software meets that criticality threshold. The repository's test counts and size do not prove external dependency or critical infrastructure status.

## Conditional concept

If external users and a security reviewer identify a material risk in one public project, propose a bounded security posture improvement: dependency and release-chain review, reproducible builds, security tests, a disclosure process, and public monthly progress reporting. Identify beneficiaries and actual dependency evidence. Do not submit a generic company funding request.

## Go/no-go gates

- Confirm project license, maintainers, external adoption, and a concrete security need.
- Check the current application calendar and whether applications are open to this project.
- Ask Alpha-Omega whether an early-stage, low-adoption project is within scope before drafting a full request.
- Obtain a security reviewer and agree to the funder's reporting/cohort commitments.
- Do not budget an award amount until the funder confirms range and eligible costs.

**Official sources:** [Alpha-Omega grant application process](https://alpha-omega.dev/grants/how-to-apply/); [seasonal grant announcement](https://alpha-omega.dev/blog/announcing-the-new-alpha-omega-seasonal-grant-program/).
