## Opening Statement

This book exists for one practical reason: to give credit where credit is due, in full view, with enough precision that readers can verify every major attribution claim.

The Unitary Manifold repository is not the work of one discipline, one institution, one person, or one machine. It is a layered construction built from physics and mathematics lineages, open-science infrastructure, software engineering ecosystems, and explicit human-AI collaboration practices. If we talk about outcomes without naming those layers, we misrepresent the work.

So this report does not flatten provenance into a ceremonial paragraph. It maps dependencies, names influences, and records responsibility boundaries.

---

## Why This Attribution Pass Is Necessary Now

A mature research repository does not become more honest by getting larger. It becomes more honest by becoming more legible.

Legibility requires three things:

1. saying which foundations were inherited,
2. saying which implementations were synthesized in-repo,
3. saying who made which decisions and who executed which systems.

This volume addresses all three. It is written as a publication-ready Substack book, with appendices in the same folder so that every citation and category can be audited directly.

---

## The Core Responsibility Partition

The project’s stated partition is straightforward and stable:

- ThomasCory Walker-Pearson provides theory, framework direction, and scientific judgment.
- GitHub Copilot (AI) provides code architecture, test suites, document engineering, and synthesis under human direction.

This partition is not branding language. It is an operating rule documented repeatedly in repository governance and outreach materials.

It matters because attribution errors can happen in two directions: overstating machine authorship of scientific judgment, or understating machine authorship of engineering and documentation scale. Both are distortions. The correct credit model is dual and explicit.

## Scientific Lineage: Physics and Mathematics Foundations

No responsible account should imply that the project invented the full language it uses. It did not.

The repository builds atop long-established structures in relativity, gauge theory, compactification, operator methods, and mathematical physics. The framework proposes a specific geometric construction and tests it aggressively, but its vocabulary and many of its evaluative standards come from decades of prior work by physicists and mathematicians.

Attribution here means naming the inherited scaffolding while being clear about what is project-specific: model choices, implementation pathways, test surfaces, and governance rules for claim boundaries.

That distinction protects both intellectual honesty and scientific readability.

---

## Data and Falsifier Lineage

The project’s strongest integrity move is not claiming certainty; it is declaring defeat conditions.

Those defeat conditions depend on external observational programs and collaborations. The repository does not own those instruments or those measurements. It depends on them.

In practice, this means credit extends beyond citations to papers: it includes the institutions, consortia, and observational pipelines that can overrule in-repo elegance. If a framework says "falsifier-first," then the experimental ecosystem is part of the attribution chain.

---

## Open-Source and Reproducibility Lineage

The repository’s reproducibility behavior rests on public tooling cultures:

- Python scientific computing conventions,
- pytest execution and regression discipline,
- transparent versioning and changelog norms,
- open issue and pull-request review workflows,
- metadata standards for citation and archival traceability.

This is not peripheral infrastructure. It is part of the epistemic engine. Without this toolchain lineage, readers could not independently inspect what was claimed, tested, or revised.

---

## Cross-Domain and Governance Lineage

The repository includes governance, justice, climate, education, and broader civic/systemic analyses. These are not silently upgraded into core-physics proof claims.

That separation itself is inherited from prior governance and methodology traditions that value bounded claims, institutional accountability, and role-aware interpretation.

The practical contribution in-repo is the enforcement layer: explicit separation files, outreach calibration, and repeated reminders about what is and is not a hardgate physics statement.

Attribution therefore belongs both to the inherited policy/governance traditions and to the specific repository mechanisms that operationalize them.

---

## AI Lineage and Tooling Credit

AI contribution in this project is neither "magic" nor "mere autocomplete." It is engineered synthesis under constraints.

Credit belongs to the model ecosystems, orchestration layers, MCP-connected workflows, and repository-level guardrails that make large-scale, auditable output possible. It also belongs to the humans who define constraints, reject weak outputs, and enforce standards.

This report deliberately avoids mythology in either direction. The machine did substantial engineering and editorial work. The human set theory direction, made judgment calls, and owned scientific accountability.

---

## On Adjacent Branch Integration and Attribution Stability

The current publication occurs while adjacent branch integration is actively in flight. That is normal for a live repository.

Attribution should remain stable across branch merges if the responsibility partition and provenance references are preserved. This is why this book uses repository-anchored citations and appendix structure rather than branch-local storytelling.

If nearby integration introduces new modules, documents, or tooling contributors, this book can be extended by appending entries to the two companion appendices without rewriting its core narrative.

---

## What This Book Contributes

This volume contributes four immediate outcomes:

1. a publication-ready narrative that can be shared now,
2. a compact attribution framework usable in future reports,
3. appendices that make provenance and credits auditable,
4. a branch-resilient structure that can absorb nearby integration updates.

It is intentionally practical: readable enough for public audiences, specific enough for critical readers, and grounded enough for maintainers who need to keep attribution accurate as the repository evolves.

---

## Closing

Credit is not a courtesy pass at the end of a manuscript. In a project like this, credit is part of methodological integrity.

If we claim rigor in equations but vagueness in attribution, the rigor is incomplete. If we claim openness but hide dependency chains, openness is performative. If we claim collaboration but flatten role boundaries, collaboration becomes propaganda.

This book is an attempt to do the opposite: show the chain clearly, name the debts honestly, and leave a record that can be checked.
