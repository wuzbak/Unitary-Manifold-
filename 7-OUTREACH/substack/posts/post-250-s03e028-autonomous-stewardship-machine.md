# Post 250 — S03E028 — The Machine That Watches Itself

The deepest upgrade in this cycle is not a single formula. It is the operational shift: the framework now carries a machine-readable loop for its own accountability.

For a long time, theory workflows depended on memory, author intent, and fragmented notes. That works until pressure hits: new data lands, contradictory results emerge, and every path to correction is manual. This repository moved past that point.

Now we have a pre-registered decision stack, explicit admissions, and an executable monitor lane that can be queried directly. The point is not to look polished. The point is to be falsifiable under load.

## What changed in practice

- Registry exports now serialize preregistered prediction lanes for DESI, SO, JUNO, SPHEREx, LiteBIRD, and HL-LHC.
- Derivation dependencies are exported as graph data, making central assumptions and downstream breakpoints inspectable.
- Admissions are no longer buried in prose; they are routable via API and included in machine payloads.

This is what scientific accountability looks like when implemented as software: hard edges, explicit labels, no hidden state.

## Why this matters now

The next 2–7 years are not quiet years for these claims. The decisive measurements are queued. If a framework waits until those results to define criteria, it is already too late. Criteria must exist before the data.

That is the purpose of this phase: lock the decision rules, expose them publicly, and make revision paths explicit.

## The honest part

There are still open lanes. That is not a failure mode; it is the definition of legitimate scientific posture. The repository keeps those lanes named, queryable, and attached to failure consequences.

The standard going forward is simple:

1. if it is claimed, it must be executable;
2. if it is executable, it must be testable;
3. if it is testable, it must carry an epistemic label;
4. if it can fail, the failure condition must be pre-registered.

That is the machine that watches itself.
